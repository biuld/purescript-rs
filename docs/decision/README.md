# Decision Records

Record only major decisions that establish long-lived architecture, constrain
compatibility, or would be costly to reverse. Ordinary implementation details
belong in the relevant design document and do not need a separate record.

Use `DEC-XX-<slug>.md`, with these sections:

1. Status and date.
2. Context and constraints.
3. Decision.
4. Consequences, including meaningful trade-offs.

Decision records preserve why a choice was made. Design documents remain the
source of truth for current architecture and implementation details.
