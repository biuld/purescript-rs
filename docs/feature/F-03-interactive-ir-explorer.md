# F-03 — PSRS Explorer

**Status:** In progress
**Design:** [D-14 — PSRS Explorer](../design/D-14-interactive-ir-explorer.md)

## User need

Learners need to understand the compiler as a sequence of explicit
representation changes. Reading a large debug dump alone makes it difficult to
answer three basic questions: what a pass consumes, what it produces, and why
the new form is necessary.

## User-visible behavior

The root-level `psrs-explorer/` application provides three connected learning
surfaces.

### Pipeline overview

The overview presents P0 through P11 on a single pipeline. It groups the
pipeline into source, frontend, and backend regions, and identifies the six
long-lived IR families. Selecting a pass opens its detail view; selecting an
IR family opens the first or last pass that owns that family.

### Representation browser

The `IRs` navigation opens a representation index rather than an arbitrary
detail page. The index lists source, intermediate forms, temporary forms, and
the final artifact; selecting one opens its contract and its incoming and
outgoing passes. On desktop, the index and selected detail share a two-column
layout. On narrow screens, the index becomes a horizontally scrollable
selection rail above the detail.

The backend representation pages list every current variant of the enums that
define CC IR, MIR, and structured Wasm, with a short explanation of each
variant's role. They also present a review of the current implementation and
the intended final design, marking completed and remaining design work while
keeping the variant inventory aligned with the code.

### Pass detail

Each pass has a stable URL and shows:

- the pass purpose, input contract, output contract, and explicit
  non-guarantees;
- an input-to-output transformation diagram for a selected sample program;
- a source-linked, readable representation view with a raw-dump alternative;
- annotations for what was added, removed, or normalized at that boundary;
- links to the governing design documentation and to the real CLI command.

The detail view must distinguish a same-representation transformation from a
representation boundary. It must also distinguish TokenStream and structured
Wasm encoding from long-lived IR families.

The `Passes` navigation opens a P0–P11 index. From there, each pass can be
opened directly, and its detail view keeps the pass list available while
showing the transformation and contract together.

### Program trace

The trace view lets the learner choose a checked-in sample program and inspect
its available snapshots in pipeline order. Selecting a source range, node, or
annotation synchronizes the related items in the other visible panes. The view
only calls an artifact an actual dump when it was generated by the compiler;
hand-authored teaching annotations are visibly identified as such.
The source and selected representation are shown side by side on desktop and
stacked in that order on narrow screens. A sample-program list stays beside
the trace on desktop and becomes a horizontal selection rail on narrow screens.

## Acceptance criteria

- The application is a typed, static browser application buildable from
  `psrs-explorer/` with documented development, test, and production commands.
- It has overview, pass-detail, and program-trace routes that work with normal
  browser navigation and deep links.
- It defines and covers all P0–P11 pass contracts without claiming unavailable
  intermediate dumps are live compiler output.
- It ships at least the checked-in `basic`, `resolved`, and `hello` examples,
  and uses generated snapshots for every currently exposed CLI stage.
- The selected pass, sample, and source range are reflected across the relevant
  panes and are keyboard operable.
- The layout remains usable at 320px wide and at desktop widths without
  horizontal page scrolling.

## Out of scope

The first version is not an in-browser compiler, editable source environment,
debugger, or substitute for the CLI. It does not invent separate snapshots for
P4, P7, P10, or P11 where the compiler does not expose a corresponding
inspection boundary.
